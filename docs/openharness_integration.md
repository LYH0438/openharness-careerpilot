# CareerPilot OpenHarness Integration

## Goal

Day 8 focuses on making CareerPilot visible as an OpenHarness-based workflow, not only as an independent Python script.

CareerPilot integrates with OpenHarness in three layers:

1. Skill layer: Markdown skills define the job-search workflow.
2. Adapter layer: `careerpilot.openharness_adapter` exposes a stable Python entrypoint.
3. CLI layer: OpenHarness `oh -p` / `oh --dry-run -p` can be used to trigger or explain the CareerPilot workflow.

## Current Integration Boundary

The current MVP does not modify the OpenHarness core agent loop.

Instead:

- OpenHarness provides the CLI prompt entrypoint and skill-driven workflow description.
- CareerPilot provides deterministic Python tools for JD analysis, resume matching, project story extraction, and application tracking.
- `careerpilot.openharness_adapter` acts as the bridge between OpenHarness-facing workflow instructions and CareerPilot's internal tool pipeline.

This approach keeps the MVP stable while preserving a clear path toward native OpenHarness tool registry integration.

## CareerPilot Adapter Command

    python -m careerpilot.openharness_adapter \
      --jd examples/careerpilot/sample_jd_backend.md \
      --resume examples/careerpilot/sample_resume.md \
      --project examples/careerpilot/sample_project_readme.md \
      --output examples/careerpilot/demo_report.md

Expected output:

    CareerPilot report generated via OpenHarness adapter: examples/careerpilot/demo_report.md

## OpenHarness Dry Run Command

    uv run oh --dry-run -p "Use career-coach skill. Analyze examples/careerpilot/sample_jd_backend.md and compare it with examples/careerpilot/sample_resume.md. Generate a job-fit report using CareerPilot."

Purpose:

- Verify that OpenHarness can accept a CareerPilot workflow prompt.
- Verify that OpenHarness can resolve configuration, prompt assembly, and static discovery checks.
- Keep the integration lightweight before full native tool registry registration.

## OpenHarness Capability Mapping

| OpenHarness Capability | CareerPilot Usage |
|---|---|
| Skills | `careerpilot/skills/career-coach.md`, `resume-rewriter.md`, `interview-prep.md` define the job-search workflow |
| Tool-use | CareerPilot tools are exposed through Python modules and the OpenHarness adapter |
| Memory | `careerpilot/memory/applications.json` stores local application state |
| CLI | `oh -p`, `oh --dry-run -p`, and `python -m careerpilot.openharness_adapter` provide command-line demo paths |
| Structured output | Tools return Pydantic-based structured outputs and Markdown reports |

## Known Limitations

- Current Day 8 integration uses an adapter instead of full OpenHarness native tool registry registration.
- The end-to-end report is still generated by CareerPilot's deterministic Python pipeline.
- OpenHarness dry-run validates startup readiness and prompt/tool/skill discovery, but does not execute the live model workflow.
- Native OpenHarness tool registration will be explored after the MVP workflow remains stable.
